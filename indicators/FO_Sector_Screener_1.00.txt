// ═══════════════════════════════════════════════════════════════════════════
// F&O SECTOR OI SCREENER 1.00 — for TradingView's Pine Screener (Premium and above)
//   Run it on a watchlist of F&O stocks' CASH symbols (for example NSE:RELIANCE), on an intraday timeframe
//   (15 min recommended: 500 candles = 20 days, enough for relative volume).
//   Every number is worked out AS AT THE LATEST CLOSED CANDLE of today's regular day (09:15–15:30).
//   A candle that is still forming is never used.
//
//   HOW IT GETS SECTOR NUMBERS IN A SCREENER (where each row is a separate run that cannot see other rows)
//     Each row also asks for ONE formula symbol that adds up its whole sector, for example
//       NSE:TCS1!_OI*3100+NSE:TCS2!_OI*3100+NSE:INFY1!_OI*1500+...
//     TradingView adds it up on its own servers, so the whole sector costs one data request.
//       Sector OI    = Σ (near + next month OI) × the stock's FIXED reference price, so a price move alone can
//                      never look like OI being added. Shown as % change and ₹ crore.
//       Sector price = Σ (cash price ÷ reference price): its % change is the sector's equal-weight price move.
//       Sector RVOL  = the price formula's volume, against its own normal (same method as the stock's RVOL).
//     Sector lists and reference prices: the SECTOR TABLE block below (generated from
//     sector_universe/FO_Sector_Universe_2026-11.csv). A stock not in the table gets sector 0 and no sector columns.
//
//   SCREENER COLUMNS (the first 10 are shown by default; add the rest with "Manage columns")
//     1  Bias           the stock's reading: +2 long build-up · +1 short covering · 0 neutral ·
//                       −1 long unwinding · −2 short build-up. Sort high to low: bullish at the top, bearish at the
//                       bottom. 2 = fresh positions (OI up), 1 = positions closing (OI down).
//                       Neutral when price or OI moved less than its band (inputs).
//     2  Price %        cash, the latest closed candle against the previous day's close
//     3  OI %           near + next month futures OI against the previous day's last prints (roll morning: the one
//                       contract both days share, as in your FCOI Screener)
//     4  OI ₹ cr        that OI change × price, in ₹ crore (assumes TradingView's OI is in shares)
//     5  RVOL %         cash volume from 09:15 to this candle ÷ the average volume from 09:15 to the same time on
//                       the last N earlier days (at least the minimum). 100 = normal for this time of day.
//     6  Sector         sector code (list below)
//     7  Sec OI %       the sector's OI change today, %
//     8  Sec price %    the sector's equal-weight price change today, %
//     9  Sec RVOL %     the sector's relative volume (empty if TradingView gives no volume for formula symbols)
//     10 Group key      ONE sort that groups the list: sort it high to low and the sectors come out ranked (by
//                       "Rank sectors by"), each sector's stocks stay together, and inside each sector the stocks are
//                       ranked (by "Rank stocks by"). A sector → stock tree in one click.
//     11 Sec bias       the sector's reading, same codes as Bias
//     12 Sec OI ₹ cr    the sector's OI change today, ₹ crore
//     13 OI % last N    the stock's OI change over the last N closed candles of today, % of the day's base
//     14 Sec OI % last N  the same for the sector: is the adding happening NOW?
//     15 vs Sector %    the stock's price % minus its sector's price %
//     16 Nifty %        NIFTY 50, the latest closed candle against the previous close
//     17 vs Nifty %     the stock's price % minus Nifty's
//     18 Sector row     1 for one stock per sector (the first in its list). Filter "= 1" and the list collapses to
//                       one row per sector; sort by Sec OI % and the sectors are ranked.
//     19 Data           0 all good · 1 contract-roll morning (OI from the shared contract / the day's first print)
//                       · 2 the stock's futures OI is missing · 3 stock not in the sector table · 4 the sector
//                       formula returned nothing · 5 sector columns switched off
//
//   SECTOR CODES
//     1 Private Banks · 2 PSU Banks · 3 NBFC and Lending · 4 Capital Markets and Insurance · 5 IT ·
//     6 Pharma and Healthcare · 7 Auto OEM · 8 Auto Components · 9 FMCG · 10 Metals and Mining · 11 Oil and Gas ·
//     12 Power · 13 Capital Goods and Defence · 14 Cement · 15 Realty · 16 Infra and Logistics · 17 Telecom ·
//     18 Consumer Durables · 19 Consumer Services · 20 Chemicals and Paints
//
//   FILTER PRESETS (the script's alert conditions; the screener offers them as yes/no filters)
//     Long build-up + high RVOL · Short build-up + high RVOL · Short covering + high RVOL · Quiet OI decline
//     (OI down, RVOL below high) · Against its sector (stock and sector readings point opposite ways) ·
//     Sector adding OI
//
//   DATA REQUESTS: exactly 5, the Pine Screener's limit: near-month OI, next-month OI, the sector OI formula, the
//   sector price formula, NIFTY 50. No timeframe, symbol or time inputs. 500 candles, like the screener.
//   No repainting: every request uses lookahead_off, values are taken only from closed candles, and nothing
//   comes from a later candle.
//   NOT TESTED ON TRADINGVIEW YET: formula symbols with _OI, their size limit and their volume are unconfirmed.
//   If the sector columns stay empty (Data = 4), run FO_Sector_Check_1.00 to find the cause.
// ═══════════════════════════════════════════════════════════════════════════

f_bias(float px, float oi, float pb, float ob) =>
    na(px) or na(oi) ? na : math.abs(px) < pb or math.abs(oi) < ob ? 0.0 : (px > 0 ? 1.0 : -1.0) * (oi > 0 ? 2.0 : 1.0)

// Relative volume, cumulative: volume from 09:15 to this candle ÷ the average volume from 09:15 to the same time
// on the last rvDays earlier days. One column per day (a ring), one row per candle slot of the day.
// Works in whichever context it runs: the chart (the stock) or inside a request (the sector formula).
f_rv(float v) =>
    var matrix<float> M = matrix.new<float>(MAXSLOT, rvDays + 1, na)
    var int   col  = 0
    var float cum  = 0.0
    var int   dKey = na
    int   mins = f_min(time)
    float out  = na
    if mins >= 555 and mins < 930
        int k = f_ymd(time)
        if na(dKey) or k != dKey
            dKey := k
            col  := (col + 1) % (rvDays + 1)
            for r = 0 to MAXSLOT - 1
                M.set(r, col, na)
            cum := 0.0
        cum += nz(v)
        int slot = math.min(MAXSLOT - 1, math.floor((mins - 555) / TF_MIN))
        M.set(slot, col, cum)
        float s = 0.0
        int   c = 0
        for j = 0 to rvDays
            if j != col
                float x = M.get(slot, j)
                if not na(x)
                    s += x
                    c += 1
        out := c >= rvMin and s > 0 and cum > 0 ? 100.0 * cum / (s / c) : na
    out

// Inside a requested symbol: this candle, the previous day's last close, today's first open, relative volume,
// and the close nBack candles ago today (na when fewer have passed today)
f_dayReq(int nBack) =>
    var float eod  = na
    var int   eodT = na
    var float dOp  = na
    var array<float> dc = array.new_float()
    if not na(time[1]) and f_ymd(time) != f_ymd(time[1])
        eod  := close[1]
        eodT := time[1]
        dOp  := open
        dc.clear()
    dc.push(close)
    float back = dc.size() > nBack ? dc.get(dc.size() - 1 - nBack) : na
    float rv   = f_rv(volume)
    [time, close, eod, eodT, dOp, rv, back]

        eod  := close[1]
        eodT := time[1]
    [time, close, eod, eodT]
